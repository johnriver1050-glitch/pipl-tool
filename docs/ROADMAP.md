# PIPL 合规工具完善路线图

更新时间：2026-07-08

## 总目标

把当前项目从“功能完整的演示版”打磨成“可信、可解释、可交付的合规辅助产品”。

成功标准：

- 用户能看懂每项义务为什么被触发。
- 每条规则能追溯到法规来源、条文、生效状态和复核状态。
- 高风险边界条件有自动化测试覆盖。
- 导出的合规文件达到可交给法务复核的初稿质量。
- AI 能力只作为辅助，不自动改写规则库或替代人工法律判断。

## 阶段 1：可信规则与边界测试

目标：先稳住合规引擎的可信度。

范围：

- 扩展规则元数据：规则类型、义务等级、复核状态、条文摘要、适用说明、例外说明。
- 更新 `KnowledgeBaseSchema`，确保知识库结构可校验。
- 在报告页展示更完整的规则解释：触发原因、法规来源、生效日期、复核状态、行动建议。
- 补充边界测试：跨境人数阈值、敏感信息阈值、零活动组织级义务、多活动去重、组合场景。

涉及文件：

- `knowledge-base/knowledge-base.yaml`
- `lib/schemas.ts`
- `lib/types.ts`
- `lib/engine/evaluate.ts`
- `app/report/page.tsx`
- `tests/engine.test.ts`

验证：

- `npm run test`
- `npm run build`

验收标准：

- 现有 13 个测试全部通过。
- 新增边界测试全部通过。
- 报告中每项义务至少显示：触发原因、来源、行动建议、复核状态。
- 未复核或草稿规则在 UI 中有明确提示。

## 阶段 2：报告可解释性与整改闭环

目标：让用户从“看到义务”进一步知道“该怎么做”。

范围：

- 为义务增加整改动作字段：`action_items`。
- 为义务增加证据材料字段：`evidence_examples`。
- 为义务增加默认优先级：`critical`、`high`、`medium`、`base`。
- 报告页按优先级展示，并保留现有 checklist。
- 存档时保存完成状态和关键版本信息。

涉及文件：

- `knowledge-base/knowledge-base.yaml`
- `lib/types.ts`
- `lib/engine/evaluate.ts`
- `app/report/page.tsx`
- `lib/archive.ts`

验证：

- `npm run test`
- 手动完成一次问卷，确认报告页解释完整、checkbox 持久化正常。

验收标准：

- 每项义务都有明确的下一步整改动作。
- 用户能区分“必须立即处理”和“一般合规待办”。
- 存档记录能反映当时使用的知识库版本。

## 阶段 3：合规文件质量升级

目标：把导出文档从骨架升级为可交付初稿。

范围：

- 隐私政策增加完整章节：处理者信息、收集清单、使用目的、共享/委托、跨境、个人权利、未成年人、更新机制。
- 单独同意书按敏感信息、共享、跨境、人脸识别、自动化决策分段。
- PIPIA 报告增加风险矩阵、控制措施、责任人、整改期限和审批区。
- 差距报告输出高/中/低优先级整改表。

涉及文件：

- `lib/templates/render.ts`
- `lib/export/docx.ts`
- `app/documents/page.tsx`
- `tests/engine.test.ts`

验证：

- `npm run test`
- 手动导出每类 Word 文档并检查打开无异常。

验收标准：

- 每类导出文档都包含法规依据、企业数据、待填写项和免责声明。
- 文档中不存在明显占位错误或空章节。

## 阶段 4：企业画像模板

目标：降低填写成本。

范围：

- 增加行业模板：普通 App、电商、SaaS、AI 应用、教育培训、医疗健康、跨境业务。
- 选择模板后预填组织特征和常见处理活动。
- 用户仍可修改所有字段。

涉及文件：

- `knowledge-base/business-templates.yaml`
- `lib/schemas.ts`
- `app/questionnaire/page.tsx`

验证：

- 手动选择每个模板并提交评估。
- `npm run build`

验收标准：

- 模板不会绕过问卷校验。
- 模板生成的处理活动能正常进入评估、报告和文档导出流程。

## 阶段 5：法规追踪审慎化

目标：让法规追踪成为安全的变更辅助，而不是自动决策器。

范围：

- 法规变化只生成“变更建议”，不自动修改知识库。
- 增加规则变更 diff：旧规则、新建议、影响页面。
- 每次规则变更记录版本号和复核人字段。
- AI 解读统一标注“待人工复核”。

涉及文件：

- `lib/legal-tracker/checker.ts`
- `app/admin/page.tsx`
- `app/api/llm/analyze-change/route.ts`
- `knowledge-base/legal-update-cache.json`

验证：

- 手动运行法规检查。
- 模拟 `possibly_updated` 状态并查看 AI 解读展示。

验收标准：

- AI 不会直接写入正式规则库。
- 管理页能清楚展示变更建议和复核状态。

## 暂缓事项

以下事项先不做，避免过早扩张：

- 多租户账号系统。
- 后端数据库持久化。
- 在线支付或商业化权限。
- 自动法律意见生成。
- 自动修改知识库规则。

## 第一批执行清单

1. 为规则 schema 增加可选元数据字段。
2. 先给 5 条高价值规则补齐元数据：敏感信息、第三方共享、跨境、未成年人、人脸识别。
3. 把元数据透传到 `Obligation`。
4. 报告页展示行动建议和复核状态。
5. 补跨境阈值边界测试。
6. 跑 `npm run test` 和 `npm run build`。
